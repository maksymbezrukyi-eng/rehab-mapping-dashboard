# Мапа надавачів послуг педіатричної реабілітації в Україні

Інтерактивний інструмент для порівняння громад за доступністю медичних і
соціальних послуг педіатричної реабілітації та віддаленістю від районних і
обласних центрів.

- GitHub Pages: <https://maksymbezrukyi-eng.github.io/rehab-mapping-dashboard/>
- Резервний Streamlit-дашборд: <https://rehabmapping.streamlit.app/>
- Репозиторій: <https://github.com/maksymbezrukyi-eng/rehab-mapping-dashboard>

## Новий dashboard відбору громад

- точки надавачів накладені на нейтральні контури громад;
- фільтри за областю, районом, медичними/соціальними послугами та кількістю
  надавачів;
- незалежні фільтри мінімальної відстані до районного й обласного центрів;
- картка громади з трьома показниками послуг і методикою відстані;
- графік «надавачі — віддаленість», упорядкована таблиця кандидатів і експорт
  повного відфільтрованого списку в CSV;
- опційний, стриманий шар віддаленості; за замовчуванням полігони не залиті;
- повністю статичний клієнтський інтерфейс без runtime-залежності від Streamlit.

Streamlit-версія залишається резервним інструментом для детального аудиту
вихідних записів.

## Що доступно у Streamlit-версії

- двомовний інтерфейс: українська та англійська;
- три рівні карти: огляд областей, контурна карта громад і кластеризовані точки;
- постійний шар справжніх меж областей без суцільної кольорової заливки;
- фільтри за територією, формою власності та пакетом НСЗУ; Київ-місто явно
  відокремлений від Київської області;
- вибір громади, перелік її закладів і картка окремого надавача;
- прозорі KPI покриття даних та окремі KPI активних фільтрів;
- сира таблиця з 21 вихідною колонкою Excel без службових полів;
- звіт про незматчені назви громад із завантаженням CSV (у поточній версії
  порожній, оскільки всі записи зіставлено).

## Як працює зіставлення

Рядок Excel прив'язується не до самої лише назви, а до конкретної фічі
`geo_id` у такій послідовності:

1. якщо рядок має статус `verified`, застосунок бере `Verified Geo ID`, але
   лише після перевірки, що такий полігон існує у поточному GeoJSON;
2. для решти рядків назва громади нормалізується, українська назва GeoJSON транслітерується за
   правилами Постанови КМУ №55;
3. пошук обов'язково обмежується областю — дані ніколи не переносяться між
   областями через однакову назву;
4. дублікати всередині області уточнюються районом;
5. якщо потрібно, тип громади (`міська`, `селищна`, `сільська`) визначається з
   назви або адреси;
6. якщо єдиного кандидата все одно немає, рядок позначається як незматчений,
   а не прив'язується навмання.

У вихідному GeoJSON обидві Талалаївські громади Чернігівської області мають
однакові властивості. Для `geo:341` виправлено підпис на Талалаївську селищну
громаду Прилуцького району; `geo:340` залишається Талалаївською сільською
громадою Ніжинського району. Поділ підтверджується державним порталом
[«Децентралізація»](https://decentralization.gov.ua/newrayons/1421/communities).

Форми власності також канонізуються. Зокрема, `NGO / Charitable` і
`NGO/Charitable` належать до `ngo-charitable`, а `Communal (hromada)` — до
`communal`; жодна фактична категорія з поточного Excel не відсікається
початковим фільтром.

## Координати точок

Точки є наближеним розташуванням закладу в межах громади, а не геокодованою
адресою будівлі. Для кожної фічі обчислюється внутрішня опорна точка, після чого
детермінований jitter розводить маркери. Кожен зсув перевіряється алгоритмом
point-in-polygon з підтримкою `Polygon`, `MultiPolygon` та внутрішніх отворів.

Регресійний тест підтверджує: усі 5 590 маркерів лежать усередині полігона
своєї громади; рядки без валідного `Geo ID` координат не отримують.

## Віддаленість від адміністративних центрів

Координати адміністративних центрів громад взяті з відкритого
[KSE Loc Data Hub](https://github.com/kse-ua/KSE-Loc-Data-Hub). Витяг охоплює
1 469 громад із кодами КАТОТТГ. Для кожної громади обчислюються дві незалежні
відстані по великому колу:

- від адміністративного центру громади до адміністративного центру району;
- від адміністративного центру громади до адміністративного центру області.

Це географічна відстань по прямій, а не автомобільний маршрут. Районні центри
визначаються в межах кожного коду району за назвою адміністративного центру;
усі 126 результатів записуються в аудиторський CSV. Найнижча подібність назви
в поточному довіднику — 0,7857. Зіставлення KSE з громадським GeoJSON охоплює
всі 1 469 громад KSE; без цього джерела лишаються Київ і дві кримські фічі.
Для Києва відстані дорівнюють нулю, але точка позначена як геометричне
наближення. Кримські фічі не отримують вигаданих відстаней.

## Встановлення та запуск

Потрібен Python 3.12.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

Шляхи до Excel і GeoJSON обчислюються відносно `app.py`, тому застосунок можна
запускати з будь-якої робочої директорії.

Щоб зібрати й локально відкрити статичну версію:

```powershell
.venv\Scripts\python.exe scripts\build_static_site.py
.venv\Scripts\python.exe -m http.server 4173 --directory _site
```

Після цього dashboard доступний на `http://127.0.0.1:4173/`. Збірка копіює
лише призначені для публікації поля: адреси та службові колонки в Pages-артефакт
не потрапляють.

## Перевірки

```powershell
.venv\Scripts\python.exe -m py_compile app.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тести контролюють:

- канонізацію та повноту категорій власності;
- рівно 21 колонку у сирій таблиці;
- унікальність `geo_id`;
- відсутність міжобласних витоків і неоднозначних збігів;
- коректні цільові полігони для відомих дублікатів назв;
- збереження всіх клітинок 21 початкової колонки Excel;
- наявність 563 перевірених `Geo ID` у GeoJSON;
- суму агрегації 5 590;
- належність кожного маркера своєму полігону;
- відсутність координат у незматчених рядків.
- наявність 5 590 публічних точок без адрес;
- покриття відстанями всіх 1 469 громад із довідника KSE;
- 126 однозначних районних центрів та нижню межу перевірки подібності назв;
- узгодженість сум медичних і соціальних надавачів у статичному наборі;
- відсутність механіки кошика у новому інтерфейсі.

GitHub Actions запускає ці перевірки автоматично на Python 3.12.

## Продуктивність

Контрольний локальний замір на повному наборі даних:

| Операція | Час | Розмір HTML |
|---|---:|---:|
| Холодний `prepare_data` | 6,0 с | — |
| Огляд областей | 0,1 с | 0,22 МБ |
| Контурна карта громад | 0,8 с | 5,11 МБ |
| Карта точок із межами областей | 1,4 с | 6,84 МБ |

Межі областей показуються завжди, а деталізація до меж громад у режимі точок
доступна як опція. Важкий ETL кешується через `st.cache_data`; фільтри
перераховують лише потрібну агрегацію.

## Відомі обмеження

- GeoJSON може не враховувати нові перейменування чи адміністративні зміни;
- точки не є адресними координатами й не мають використовуватися для навігації;
- адміністративні відстані є відстанями по прямій, а не часом у дорозі;
- точність KPI залежить від повноти та коректності вихідної таблиці.

Перед заміною Excel або GeoJSON потрібно запустити весь набір тестів і свідомо
оновити очікувані контрольні числа, якщо змінився сам набір даних.
